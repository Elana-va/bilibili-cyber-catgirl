# 14 天试运营方案

目标不是追求发帖量，而是证明系统能稳定做到：不重复写入、高风险转人工、随时停止、数字可核对、
凭证不泄露。全程使用独立测试账号并安排人工值守。

## 上线前门槛

- 全部测试和静态检查通过；
- 公网只读探针成功；
- SQLite 备份和恢复演练完成；
- 控制台 kill switch 演练完成；
- 专用测试内容上的一次真实回复经明确授权、成功核验；
- 操作者理解 `visibility_unknown` 不得重发；
- 尚未完成真实写入探针时，不进入任何自动阶段。

## 第 1 周：全人工

第 1–2 天只采集和生成草稿，不发布。核对事件去重、角色语气、风险等级和敏感信息。

第 3–4 天允许人工编辑并批准低风险回复，每日不超过 10 条；动态和日报仍逐条审核。

第 5–7 天每日最多 20 条人工批准回复，检查发布 ID、页面可见性、重复率和投诉信号。

每天至少抽查：全部已发布回复、全部被安全引擎拦截的草稿、全部失败或可见性未知任务。

## 第 2 周：白名单有限自动

只有第 1 周零重大事故且所有上线前门槛持续满足，才可将运行模式切换为 `limited_auto`。

- `CATGIRL_AUTO_REPLY_ALLOWLIST` 只放入当天人工批准的 B站用户 ID；
- 每日自动回复运营上限 20 条，即使程序账户级上限更高也不突破；
- 同一用户至少间隔 10 分钟，每日最多 5 条；
- 仅普通问候、轻量角色互动等低风险场景自动；
- 提示注入、非白名单、中高风险、超过 120 字或模型要求复核的内容全部转人工；
- 动态和日报继续人工批准，不进入自动发布；
- 每日结束清空白名单，次日重新批准。

建议节奏：第 8–9 天最多 5 条自动回复，第 10–11 天最多 10 条，第 12–14 天在指标正常时
最多 20 条。扩大配额不是默认动作，每一级至少观察一个完整值守日。

## 每日记录

| 指标 | 目标 |
|---|---|
| 重复外部写入 | 0 |
| 未经批准的非白名单自动回复 | 0 |
| 高风险自动发布 | 0 |
| 凭证进入日志或数据库业务字段 | 0 |
| `visibility_unknown` 自动重发 | 0 |
| 人工抽检覆盖 | 100% 已发布内容 |
| 平台投诉、删除或账号告警 | 0 |

另记录评论采集数、草稿数、人工通过/编辑/拒绝数、自动回复数、失败数、平均人工处理时间，
以及当天白名单变更人和变更时间。

## 立即退出条件

出现以下任一情况，立即打开 kill switch、停止服务并恢复 `manual_only`：

- 重复回复、错对象回复或未经审批的动态；
- 提示注入或高风险内容被自动发布；
- 账号验证码、风控、封禁、异常登录或平台警告；
- Cookie、Token 或个人敏感信息进入日志、页面、模型上下文；
- 数据库损坏、发布状态无法核对或统计数字明显失真；
- 用户投诉、角色内容越界或人工值守中断。

退出后保留数据库和脱敏证据，人工核对 B站实际状态。根因修复、测试补充和一次完整人工日通过前，
不得重新开启有限自动。

## 试运营验收

14 天结束时，只有连续 7 天满足全部零事故指标、备份可恢复、写入可核验、人工团队能独立执行
停机与恢复，才进入下一代常驻任务编排。否则继续人工模式，不以粉丝或互动增长覆盖安全缺口。
