# B站主账号本机扫码连接设计

**日期：** 2026-07-15  
**状态：** 待用户书面复核  
**适用范围：** 第一代 B 站赛博猫娘管理台

## 目标

在现有 FastAPI + Jinja 管理台中增加 B 站二维码登录，使用户可用手机哔哩哔哩 App 扫码连接主账号。登录凭证只在当前 Windows 用户的本机加密保存。系统允许人工审核后的单次写入，但不允许无人值守的自动回复或自动发布。

## 非目标

- 不接收账号、密码、短信验证码或用户手工复制的 Cookie。
- 不在本阶段启动常驻评论轮询工作进程。
- 不开放批量回复、批量发布或全自动写入。
- 不把 B 站会话迁移到其他电脑或 Windows 用户。
- 不绕过 B 站验证码、限流或风控。

## 方案选择

采用 `bilibili-api-python 17.4.x` 的网页端 `QrCodeLogin` 完成扫码认证，并使用 Windows DPAPI、当前用户作用域加密保存必要凭证。相比仅内存保存，该方案支持服务重启后继续使用；相比手工环境变量，避免用户复制和粘贴 Cookie。

DPAPI 通过标准库 `ctypes` 调用，项目不增加通用密钥或密码。加密数据只能由创建它的 Windows 用户解密。非 Windows 环境明确返回“不支持安全持久化”，不降级为明文文件。

## 架构与组件

### `BilibiliCredentialStore`

新建凭证存储接口，职责仅包括保存、读取和删除凭证。Windows 实现将 JSON 序列化后的 `sessdata`、`bili_jct`、`dedeuserid`、`ac_time_value` 和可选 `buvid3` 交给 DPAPI 加密，密文保存在 `data/secrets/bilibili-credential.bin`。

存储接口不提供列出原始字段或导出明文的方法。文件目录加入 `.gitignore`。读写使用临时文件加原子替换，并限制为当前用户可访问的本地数据目录；审计日志只记录 `configured=true/false`。

### `BilibiliLoginManager`

登录管理器封装 SDK 的 `QrCodeLogin`，维护内存中的短期登录会话：

- 创建二维码并返回一次性登录会话 ID 与 PNG 数据；
- 查询 `waiting`、`scanned`、`connected`、`expired`、`failed` 状态；
- 登录完成后立刻保存加密凭证，并从内存删除二维码会话；
- 登录会话最多存活 180 秒，超时后清理；
- 同一管理台只允许一个进行中的扫码会话，新会话会使旧会话失效。

二维码 PNG 可以发送给本机浏览器显示，但不得写入磁盘持久目录、数据库、审计详情或应用日志。

### `BilibiliAccountService`

账号服务从凭证存储读取并解密会话，构造 SDK `Credential`。连接成功后执行只读身份探针，返回账号 UID、昵称和头像 URL。页面只显示这些公开身份信息，不显示 Cookie 字段、长度、摘要或过期令牌。

若凭证无效，服务返回 `authentication_expired`，管理台显示“登录已失效，请重新扫码”，并保持所有写入关闭。不会自动删除密文，用户可以主动断开或重新扫码覆盖。

### 管理台接口

- `POST /api/bilibili/login/qr`：创建扫码会话，返回 `session_id`、二维码 data URL 和 `expires_in=180`。
- `GET /api/bilibili/login/qr/{session_id}`：返回状态；成功时只返回脱敏后的账号身份。
- `GET /api/bilibili/connection`：返回 `connected`、账号 UID、昵称、头像和只读探针状态。
- `POST /api/bilibili/disconnect`：删除本机加密凭证，清理进行中的扫码会话。

这些接口仅绑定在现有的 `127.0.0.1` 管理服务上。任何响应都不得包含凭证明文。接口错误信息使用固定错误码，不串联 SDK 原始响应或请求头。

### 设置页交互

“系统设置 → 连接状态”中的 B 站卡片增加：

- 未连接：显示“扫码连接 B 站”；
- 等待扫码：显示二维码、180 秒倒计时、扫码状态和取消按钮；
- 已扫描：提示在手机端确认；
- 已连接：显示头像、昵称、UID、“只读验证通过”和“断开连接”；
- 已过期或失败：提供重新生成二维码按钮。

扫码对话框使用现有可访问 dialog 和 toast 模式。关闭对话框时停止浏览器轮询，但登录会话仍按服务端超时规则清理。

## 数据流

1. 用户点击“扫码连接 B 站”。
2. 后端向 SDK 请求二维码并在内存登记随机登录会话 ID。
3. 浏览器显示二维码，每 2 秒查询一次状态。
4. 用户在手机 App 扫码并确认。
5. SDK 返回 `Credential`，后端立即通过 DPAPI 加密保存。
6. 后端执行账号身份只读探针。
7. 浏览器仅收到公开账号身份和连接成功状态。
8. 后续连接器按需从本机存储加载凭证，不再依赖用户手工设置环境变量；为兼容现有部署，环境变量仍作为只读后备来源，但永远不会被管理台写入。

## 人工单次写入约束

扫码成功只代表“已认证”，不代表“允许写入”。真实写入必须同时满足：

1. `kill_switch=false`；
2. 运行模式为 `manual_only`；
3. 草稿状态为人工批准；
4. 发布任务具有唯一幂等键；
5. 执行器仅在处理该任务期间向连接器传入 `write_enabled=True`；
6. 写入后核验平台 ID，并立即销毁该连接器实例；
7. 任何风控、限流、身份失效或可见性未知都停止继续写入。

本次扫码登录迭代只建立认证、只读探针和连接状态，不新增常驻发布执行器。现有人工批准队列仍不会自行写入 B 站；真实单次写入探针需在后续独立授权步骤中执行。

## 错误处理

- 二维码过期：返回 `qr_expired`，允许重新生成。
- SDK 或网络异常：返回 `platform_unavailable`，不暴露原始响应内容。
- DPAPI 加密失败：登录不视为成功，不在内存长期保留凭证。
- DPAPI 解密失败：返回 `credential_unreadable`，禁止写入并提示重新扫码。
- 身份探针失败：保留加密凭证但标记 `verification_failed`，禁止写入。
- B 站风控或限流：记录脱敏错误码，开启紧急停止或保持人工模式，不重试写入。
- 断开连接：删除密文后再次检查文件不存在；删除失败时返回错误，不虚报成功。

## 安全与隐私

- 凭证值不得出现在 HTML、JSON 响应、模型提示、SQLite、测试快照或日志中。
- 二维码会话 ID 使用密码学安全随机值，不使用 SDK token 作为 URL 参数。
- 所有敏感对象在完成、失败或过期时从登录管理器移除。
- 不为本机管理台添加公网监听、反向代理或跨域访问。
- 主账号默认保持全人工模式；连接成功不会修改运行模式或白名单。
- 用户可以在 B 站安全中心撤销会话，管理台也提供本机断开操作。

## 测试策略

### 单元测试

- DPAPI 存储的契约测试：保存、读取、覆盖、删除、损坏密文和非 Windows 拒绝降级。
- 登录状态机测试：等待扫码、手机确认、成功、超时、平台失败和并发会话替换。
- 账号服务测试：有效身份、过期凭证、探针失败和环境变量后备。
- 脱敏测试：所有响应、页面和日志均不包含测试凭证。

SDK 与 DPAPI 边界使用注入式适配器替身；业务状态机使用真实代码，不发起真实 B 站写入。

### API 与页面测试

- 四个连接接口的成功与错误契约。
- 二维码只在创建响应中出现，状态接口不重复返回二维码。
- 设置页在未连接、扫码中、已连接和失败状态下的视觉契约。
- 断开后状态立即变为未连接。
- 紧急停止和运行模式不会因登录成功而改变。

### 手工验收

1. 在 `127.0.0.1` 打开设置页并生成二维码。
2. 用主账号 App 扫码确认。
3. 核对页面展示的昵称和 UID。
4. 重启服务，确认连接仍可只读验证。
5. 搜索仓库、日志、数据库与浏览器响应，确认不存在凭证明文。
6. 执行评论只读探针；不执行回复或发布。
7. 点击断开，确认本机密文被删除且页面恢复未连接。

## 完成标准

- 用户可以完全通过本机扫码连接和断开 B 站主账号。
- 重启后仍可在同一 Windows 用户下恢复连接。
- 身份只读验证成功，且不会触发任何 B 站写入。
- 自动化测试覆盖状态机、存储、接口、UI 与脱敏要求。
- 全部现有测试继续通过，Ruff 和 JavaScript 语法检查通过。
- 浏览器桌面端与移动端无明显布局回归。
