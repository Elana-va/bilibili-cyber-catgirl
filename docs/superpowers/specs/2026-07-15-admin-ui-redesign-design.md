# 小喵创作室完整运营后台设计

日期：2026-07-15  
状态：已确认，待实施

## 目标

把当前单页审核界面升级为完整、可日常值守的 B站赛博猫娘运营后台。后台的首要任务是让操作者快速判断系统是否安全、有哪些内容需要审核、最近发生了什么，并能在任何页面立即停止外部写入。

本次改版只优化本机运营后台，不改变 B站连接器的授权边界，不开启真实账号写入，也不加入直播、私信、视频投稿、多账号或验证码处理。

## 已确认方向

- 视觉方向：B站粉蓝创作室；
- 导航骨架：左侧工作区；
- 角色资产：定制粉蓝赛博猫娘立绘；
- 技术路线：FastAPI + Jinja 多页面 + 少量原生 JavaScript；
- 功能范围：工作台、审核中心、内容计划、互动数据、运行日志、系统设置六个页面。

## 视觉系统

### 设计主题

界面以“猫娘的创作工作室”为主题，不做常见的黑底霓虹赛博后台。页面使用轻盈的粉蓝空间、清晰的数据层级和克制的角色元素。猫娘立绘是唯一的大型装饰元素，只出现在工作台欢迎区和空状态，其他页面保持安静、专业。

### 色彩令牌

| 名称 | 色值 | 用途 |
|---|---|---|
| Sakura | `#FB7299` | 主行动、当前导航、审核按钮 |
| Sky | `#23ADE5` | 信息状态、链接、次要强调 |
| Ink | `#27304A` | 标题和主要文本 |
| Blossom | `#FFF4F8` | 侧栏和柔和背景 |
| Canvas | `#FFFAFD` | 主画布 |
| Success | `#25A782` | 在线、成功、已核验 |
| Warning | `#E7A23C` | 中风险、等待处理 |
| Danger | `#D94366` | 紧急停止、失败、高风险 |

正文使用本机中文系统字体栈，避免网络字体造成离线失败。英文状态标签使用更紧凑的字距和大写形式，与中文标题形成角色工作室的仪表感。

### 标志性元素

工作台欢迎区使用定制粉蓝赛博猫娘半身立绘，搭配轻量扫描环或状态光带。动画只在首次加载发生一次，并尊重 `prefers-reduced-motion`。界面其余位置不重复大型插画，避免削弱运营信息。

## 信息架构

### 全局框架

桌面端使用常驻左侧导航，包含品牌、六个页面入口和底部安全摘要。主区域顶部显示当前页面、运行状态和紧急停止按钮。紧急停止在每个页面保持相同位置。

移动端将侧栏折叠为底部导航，低频页面进入“更多”菜单；数据表转为卡片列表，主要操作保持单手可达。

### 工作台 `/`

工作台展示：

- 当前日期、运行模式、kill switch、B站连接状态；
- 今日新评论、已回复、待审核和异常任务；
- 最新待审核草稿；
- 最近运行事件；
- 指向审核中心的主行动按钮。

所有数字来自 SQLite。没有数据时显示 `0` 和说明，不使用虚构演示数字。

### 审核中心 `/reviews`

审核中心按回复、动态、日报分类，支持状态、风险等级和关键词筛选。每条草稿显示来源、生成时间、风险、内容和统计快照。

允许查看、编辑后批准、直接批准和拒绝。批准和拒绝均需确认；禁止批量批准。`visibility_unknown` 只提供“查看详情”和人工核验说明，不提供直接重发。

### 内容计划 `/content`

内容计划提供日历和列表两种视图，展示定时动态、日报计划、执行时间和启用状态。新增或编辑计划只改变草稿生成安排，不直接创建外部发布。

第一代支持查看、创建、启用、停用和编辑现有的 `ScheduledContentRecord`。普通内容在 23:00–08:00 的静默期规则保持不变。

### 互动数据 `/analytics`

互动数据读取 `DailyMetricRecord`，展示最近 7 天和 14 天的评论数、回复数、独立用户、人工审核数和失败数。趋势图使用本地原生 SVG 或 CSS，不引入第三方图表库。

当日期缺失时图表保留时间轴并显示无数据状态，不进行插值或推断。

### 运行日志 `/logs`

运行日志统一展示发布任务和审计事件，支持按时间、动作和状态筛选。发布任务显示幂等键、尝试次数、平台 ID 和最终状态；审计详情在服务端递归脱敏后才能进入模板。

凭证、Cookie、Authorization 和模型密钥不得出现在 HTML、查询参数、JavaScript 或错误消息中。

### 系统设置 `/settings`

设置页管理运行模式、自动回复白名单、轮询间隔和 kill switch。B站与模型凭证只显示“已配置/未配置”，不提供读取、复制或回显值的接口。

切换到 `limited_auto` 前必须满足非空白名单；否则服务端拒绝并解释原因。保存设置使用明确的成功或失败反馈。

## 服务端结构

### 路由边界

现有 `web/routes.py` 拆分为：

- `web/pages.py`：六个服务器渲染页面；
- `web/actions.py`：批准、拒绝、设置和 kill switch 等写操作；
- `web/view_models.py`：模板使用的只读 Pydantic 视图模型；
- `services/dashboard.py`：统计、筛选、趋势和日志查询。

`main.py` 只负责应用装配、静态文件和路由注册。现有 API 路径保持兼容，避免破坏测试和后续调用方。

### 模板和静态资源

- `templates/base.html`：全局框架、侧栏、顶部状态栏；
- `templates/dashboard.html`：工作台；
- `templates/reviews.html`：审核中心；
- `templates/content.html`：内容计划；
- `templates/analytics.html`：互动数据；
- `templates/logs.html`：运行日志；
- `templates/settings.html`：系统设置；
- `templates/components/`：状态徽章、空状态、分页和确认对话框；
- `static/app.css`：设计令牌和响应式布局；
- `static/app.js`：导航、筛选、对话框、Toast 和安全操作；
- `static/catgirl-mascot.png`：定制角色资产。

## 数据流

主业务流保持：

```text
B站评论
  → 去重入库
  → Agent 生成结构化草稿
  → 安全引擎判定
  → 人工审核或白名单有限自动
  → 幂等发布任务
  → 平台可见性核验
  → 日志与每日指标
```

页面只通过查询服务读取领域记录。写操作继续调用现有审核和设置逻辑，不允许模板或 JavaScript 直接操作数据库。

## 错误与空状态

- 页面无数据时说明当前状态和下一步，不显示大片空白；
- API 失败显示带具体原因的 Toast，并保留用户尚未提交的编辑内容；
- 危险操作使用应用内确认对话框，不使用浏览器默认 `alert` 或 `confirm`；
- kill switch 使用高辨识度确认框，成功后立即刷新全局状态；
- 数据库或连接器不可用时，页面进入只读降级状态，不创建外部写任务；
- `visibility_unknown` 明确标记为终态，提示到 B站人工核验。

## 安全约束

- 默认 `manual_only` 和空自动回复白名单；
- 前端不能绕过服务端安全判定；
- 所有真实发布仍经过 `PublishJobRecord` 和 `Publisher`；
- 凭证只从进程环境读取；
- 日志和模板上下文必须脱敏；
- 不提供批量批准、未知状态重发或验证码绕过入口；
- 管理后台继续只绑定 `127.0.0.1`。

## 验证标准

自动测试覆盖：

1. 六个页面返回 200 且导航状态正确；
2. 工作台统计来自数据库，不使用硬编码数字；
3. 审核筛选、编辑、批准和拒绝正确；
4. 内容计划创建、编辑、启停遵守静默期和草稿约束；
5. 趋势数据正确处理缺失日期；
6. 日志筛选和递归脱敏正确；
7. 空白名单不能开启有限自动；
8. kill switch 取消待发布任务并阻止批准；
9. HTML 和 API 不包含测试凭证字符串；
10. 现有领域、连接器和端到端测试全部继续通过。

视觉验证覆盖 1440px 桌面、1024px 窄桌面和 390px 手机宽度，检查溢出、焦点、对比度、空状态、确认框和减少动画模式。

## 非目标

本次不接入真实账号凭证，不执行 B站写入，不实现用户登录、远程公网部署、WebSocket 实时推送、React/Vue、第三方图表库、直播、私信、视频投稿或多账号管理。
