# B站连接器第一代验证记录

验证时间：2026-07-15（Asia/Shanghai）

## 实现范围

- 连接器基于 `bilibili-api-python 17.4.2`，业务层只依赖项目自己的
  `BilibiliPort` 接口，便于后续替换 SDK。
- 已实现评论读取与标准事件转换、评论回复、图文动态发布、发布结果核验。
- 登录信息仅从进程环境变量 `BILI_SESSDATA`、`BILI_JCT`、`BILI_BUVID3`
  读取，不写入配置文件、数据库或审计日志。
- 所有真实写操作必须同时满足：凭证存在、连接器 `write_enabled=True`、
  上层发布审批通过。默认值为关闭。
- SDK 返回限流、账号异常或风控代码时，会转换成明确的领域异常；风控异常会调用
  回调，供运行时切换人工模式。

## 已完成验证

单元测试通过以下场景：

1. 无凭证时拒绝写入；
2. 只读响应能转换成统一评论事件；
3. `-412` 等风控错误会触发人工模式回调；
4. 能力探针在只读模式下不会调用任何写方法；
5. 探针报告以 UTF-8 JSON 保存。

公开网络只读探针：

- 目标：视频 `av170001`（oid `170001`）
- 结果：接口请求成功，`comment_read=true`，本次响应解析到 0 条评论；
- 写入：未执行，`comment_write=false`；
- 报告：`artifacts/connector-readonly.json`（本地运行证据，不提交仓库）。

## 尚未执行的验证

真实评论回复和动态发布探针没有执行。它们会改变外部账号状态，需由操作者：

1. 在本机进程环境设置 B站凭证；
2. 提供专用测试稿件或动态目标；
3. 明确批准一次写入；
4. 写入后核验平台 ID，并立即恢复写入闸门为关闭。

不得在聊天、源码、`.env` 示例或报告中粘贴真实 Cookie。第一代上线前还应在专用小号、
低频率和人工监看条件下完成这一项。
